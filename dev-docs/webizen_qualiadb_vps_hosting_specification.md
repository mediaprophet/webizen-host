## 1. Executive Summary: Human-Centric Semantic Hosting for Natural Persons, Groups & Agents

Operating public ontological infrastructure and human-centric web and application services on conventional cloud platforms exposes independent stewards and communities to unbounded financial liability and architectural lock-in. The operational experience of [ns.webcivics.net](https://ns.webcivics.net/)—which serves machine-readable human rights instruments and legal logic—demonstrated two acute failure modes of legacy infrastructure: standard repositories and tools fail when importing large ontological repositories exceeding 100 MB such as [WebCivics/ns](https://github.com/WebCivics/ns), and commercial content delivery networks (such as AWS CloudFront) lack hard protocol-level cost circuit breakers when concentrated traffic spikes arrive from major US data hubs. At the same time, legacy server control panels such as cPanel/WHM remain wedded to monolithic LAMP stacks, ICANN DNS-as-identity assumptions, and static file hosting that cannot natively execute QualiaDB/Webizen applications or stream 48-byte semantic graph records (`NQuin`s).

The **Webizen Web-Host Server Stack (`webizen-host`)** is a comprehensive, **Human-Centric** VPS hosting platform, native QualiaDB/Webizen application server, and full cPanel replacement engineered on the [QualiaDB and Webizen stack](https://webizen.au/). Designed for installation on commodity Linux Virtual Private Servers (VPS) or as an online federated relay extending a locally installed `webizen-desktop` and `qualiadb` environment, the platform supports **both human groups (individuals, families, communities, cooperatives, and organizations) and agents (natural person agents, group/cooperative agents, and capability-bounded software/AI agents)**. It transforms every hosted server into a native QualiaDB/Webizen application runtime, a multi-tenant sandbox host, a high-speed [Qualia Decentralized Network Fabric (QDNF)](https://webizen.au/qdnf.html) routing and DNS node, and a self-funding edge peer in a user-powered decentralized CDN. By building the hosting control plane directly on `qualia-core-db`, `qualia-client-core`, `vibe`, `poet`, and `qualia-peer`, deploying the hosting stack directly exercises, hardens, and closes the remaining integration gaps in the core QualiaDB monorepo.

## 2. Deployment Topologies & Stack Symbiosis

The platform supports two primary installation modes that share a single binary and crate boundary (`qualia-core-db` → `qualia-client-core` → `webizen-host` / `webizen-desktop`), ensuring that server-side work directly advances the desktop and browser ecosystems documented in the [Qualia · Webizen · Poet Release Matrix](https://webizen.au/release-matrix.html).

### 2.1 Mode A: Standalone Human-Centric VPS Host
Installed on any standard Linux VPS (Debian/Ubuntu/Alpine/NixOS on x86_64 or ARM64, minimum 2 vCPU / 4 GB RAM for baseline hosting, scaling to dedicated NVMe/ZNS storage and optional Vulkan/WebGPU compute adapters per [Optimizing WGPU for AI and QualiaDB](https://docs.google.com/document/d/1MzQRXk2l0-Eji_h48uC08XYWMvyjfuzU-qoWmT-7bnU/edit)). A single CLI command (`qualia-cli host init --profile=vps-human-centric`) provisions:
- **The Native Daemon & App Host (`services/daemon.rs` on `:4242` & HTTPS/QUIC `:443`)**: Manages `.q42` volumes, `.hmc` bundles, `.10d` spatial containers, `QApp` registries (`q42/app_registry/`), `SlgArena` logic workers, `agent_runtime/` orchestrators, and the `qualia-solid-bridge` W3C Solid/LDP compatibility pod server (as deployed on [web.civics.au](https://web.civics.au/)).
- **The QDNF / QPR Edge Router**: Runs the native Qualia Peer Runtime (`crates/qualia-peer` `PeerHost`), `CSCP` control plane (`Wave 0–1` TLV codec, leases, receipts), and public transition bearers (WireGuard `SocialWebNet`, TLS WSS, HTTP/2 Extended CONNECT, and **CSCP-08** public MASQUE bound-UDP relay endpoints).
- **The Ontology & Asset Cooking Worker**: Executes bounded cold-path compilation of massive external git/HTTP ontology repositories (such as [WebCivics/ns](https://github.com/WebCivics/ns)) and 3D/10D hypermedia assets into segmented `.q42`, `.10d`, and `.hmc` distributions without exhausting system memory.

### 2.2 Mode B: Online Extension to Local `webizen-desktop` / `qualiadb`
As outlined in the [Webizen 3.0 Host Service Requirements](https://devdocs.webizen.org/WebizenTechStack/Webizen3.0/HostServiceRequirements/) and [Webizen Pro](https://devdocs.webizen.org/WebizenTechStack/Webizen3.5/WebizenProSeries/WebizenPro/) specifications, a VPS instance can pair cryptographically with a person's, family's, or group's local `webizen-desktop` installation (running locally on `:8080`).
- **Cryptographic Pairing & Sanctuary Keep Protection**: Using `PeerHost::pair` and `did:qi` mutual authentication (ML-KEM-768 post-quantum handshakes in `net/qdnf/crypto/handshake/` + Ed25519 signatures), the VPS acts as an always-on public ingress, delegated hostname provider (`mylaptop.mydomain.tld`), encrypted mailbox store-and-forward node, and public `.q42`/`.hmc` mirror.
- **Strict "Church & State" Vault Separation**: In accordance with [GuideForDevelopers](https://devdocs.webizen.org/GuideForDevelopers/) and the [Webizen Desktop Application Requirements](https://docs.google.com/document/d/1B2Zz1MqZKJgqWtKPxPqDD4_LFIAJt1CXYHWb9utrj5E/edit), the platform enforces a hard architectural boundary between:
  - **The "Church" Database (`TheWebizenAgent` / Sanctuary Keep)**: Deeply personal biographical, clinical (`wellfare-core`), and unshared personal thought/consciousness records that remain strictly on the user's local hardware outside OS cloud-sync folders, protecting *Freedom of Thought* and *Safety Protocols*.
  - **The "State" Database (`PermissiveCommonsTech` on the VPS)**: Shared social records, group workspaces, native Webizen apps, and `ValuesCredentials`-governed ontologies (`entity_view/rights_filter.rs` and `net/qdnf/policy_labels/` Information Flow Control lattice). Off-site disaster recovery backups of the local vault are stored only as client-encrypted `.q42j` journal replicas (`q42/journal.rs`) recoverable via M-of-N Shamir secret shares.

Building and operating `webizen-host` is explicitly scoped to resolve six high-priority engineering gaps identified in the [QualiaDB Capability Reference (0.0.40)](https://docs.google.com/document/d/1kKTwYKm9G333hKjclleAhwx2O-hVjv_v6htm_IL2kf8/edit):

## 3. Large Ontology Ingestion, Processing & Segmented Hosting Pipeline (`>100MB` `WebCivics/ns`)

A primary driver for the platform is the inability of standard cloud tools and browser environments to import, reason over, and serve massive ontology repositories such as [WebCivics/ns](https://github.com/WebCivics/ns) (>100 MB of RDF/XML, Turtle, N3, OWL, and human-rights / legal vocabularies) alongside external scientific corpora (ChEBI, SNOMED, QUDT, WordNet, GBIF, ABS statistics).

### 3.1 Bounded Cold-Path Streaming Ingestion Architecture
To prevent out-of-memory (OOM) crashes on affordable VPS instances while honoring QualiaDB's two-tier allocation contract (`AGENTS.md` §0-A), the ingestion pipeline operates as a streaming **Tier 2 `ColdBounded` Service** (`q42/asset_import/` + `qualia-cli/src/ingest/`):
1. **Git / Archive Chunk Puller**: Clones or pulls [https://github.com/WebCivics/ns](https://github.com/WebCivics/ns) (including Git LFS or multi-hundred-megabyte RDF/Turtle trees) into a staging volume (`/var/lib/qualia/staging/ns/`), computing BLAKE3/SHA-256 source digests per file and checking upstream licenses via `q42/asset_envelope/`.
2. **Streaming Lexical & Triple Parser (`query/ingest*.rs`, `n3_parser.rs`)**:
   - Streams RDF/XML, Turtle, N-Triples, JSON-LD, YAML-LD (`yaml_ld_q42.rs`), and Notation3 (`=>` strict, `~>` defeasible, `^>` defeater, `-o` linear rules) under an explicit caller byte budget (default `256 MiB` cold arena, configurable up to VPS RAM cap, failing closed with quarantine counts on malformed records).
   - **Mandatory `IngestMode::Complete` with `Q42LEX v4`**: All public ontology builds enforce `IngestMode::Complete` coupled to the **v4 namespaced paged lexicon (`q42_lex_ns.rs`)**. Unlike `StripLiterals` (which discards string literals), `Q42LEX v4` interns namespace prefixes and stores 60-bit masked tokens (`u16` term length ≤ 65,535 B) in range-addressable lexicon pages, while computing compile-time/ingest-time 64-bit FNV-1a hashes (`q_hash()`) for zero-heap hot-path unification.
3. **SHACL-First & Non-Thing Ontological Uplift (`owl/shacl_convert.rs`)**:
   - Enforces the normative policy in `docs/manuals/standards/shacl-first-vs-owl-ok-class-list.md`: **natural persons, kinship, human relations, and living ecological entities are strictly forbidden from subclassing `owl:Thing`**.
   - During ingestion of legacy OWL ontologies in `WebCivics/ns`, the compiler automatically runs `owl/shacl_convert.rs` to lift class constraints regarding persons, rights-bearers, and living entities into **W3C SHACL shapes** (`shapes/*.shacl.ttl`) and N3 deontic rules (`SlgOpcode` bytecode `0x10–0x44`), while keeping artifact descriptors (`q42:Volume`, protocols, containers) in standard OWL-compatible classes.

### 3.2 Segmented Compilation into `.q42` v4 & `QBDL` `.hmc` Containers
Rather than serving a single >100 MB monolithic file, the compiler partitions `WebCivics/ns` and other large corpora into an **RDF Geometry of Graphs** packaged as segmented, HTTP-range-addressable volumes:

| Output Format | Binary Structure & Alignment | Role in Hosting Large Ontologies (`WebCivics/ns`) | Client / Mobile / WASM Consumption Pattern |
| :--- | :--- | :--- | :--- |
| **`.q42` v4 Semantic Volume** (`q42_volume.rs`) | 64-B header + 40,960-B LZ4-compressed `QualiaSuperBlock`s (853 × 48-byte `NQuin`s per block) + `BIDX` block index + postings index + `Q42LEX v4` paged lexicon | Encodes every semantic statement as a 48-byte `NQuin` (`subject`, `predicate`, `object` with inline scalar tags `0b001<<60` int / `0b101<<60` float or MSB=1 `did:q42` pointer, `context` Named Graph DID, `metadata`, `parity`). | Clients read the 64-B header + `BIDX` index via `range_volume.rs` and fetch **only the specific 40 KiB SuperBlocks** matching their SPARQL/N3 query—reducing a 150 MB ontology lookup to a <100 KiB transfer. |
| **`QBDL` `.hmc` Hypermedia Bundle** (`bundle/format.rs`) | Magic `QBDL` v1, 64-B header, 64-B page-aligned intact entries, trailing CBOR index footer (`key`, `kind`, `offset`, `length`, `sha256`, `meta`), whole-file CRC-32C + `cbor_ld_manifest.rs` | Packages domain-sharded `.q42` sub-volumes, compiled `SlgOpcode` law packages (`governance/law_packages.rs`), `.10d` spatial/sensory manifolds, and multi-language prose (`PayloadCatalogueEntry`). | Because `entry.offset + seg.offset` is 64-byte aligned and indexed in the CBOR footer, any HTTP/2 server or QPR peer serves exact interior byte slices (`206 Partial Content`) with per-entry SHA-256 verification. |
| **Content-Negotiated Virtual Namespace Server** | Dynamic projection from `.q42` + `Q42LEX v4` | Replaces static Apache/Nginx directory listings on `ns.webcivics.net` with a zero-alloc Rust handler that resolves any ontology URI (`https://ns.webcivics.net/<domain>/<term>`). | Returns `application/q42` (binary `NQuin` slice) or `application/cbor-ld` to Webizen clients, and dynamically serializes `text/turtle`, `application/n-triples` (`resolver.rs::format_ntriples_to`), `application/ld+json`, or interactive HTML+WASM documentation for legacy semantic web tools. |

## 4. Human-Centric Ownership, Groups, and Agent Governance Models

A foundational requirement of the Webizen platform is that systems are **Human-Centric** and support **both groups (many natural persons, families, communities, cooperatives) and agents (natural person agents, group/cooperative agents, and governed software/AI instruments)**—without ever confusing instruments/bots with peer natural persons.

### 4.1 Decoupling the Who-Plane (`NaturalAgent`) from the Handle-Plane (`DNI` / DNS)
In strict compliance with [QDNF Continuity Rules](https://webizen.au/qdnf.html) and [Honest Progress 0.0.26](https://webizen.au/progress-0.0.26.html):
- **Who-Plane (`Identifier Fabric`)**: Every human steward or member is represented as a `NaturalAgent` (never `owl:Thing`, never a corporate wallet) anchored by self-certifying `did:qi` (`did_qi/` signed `QCDE-1` lifecycle vectors) and `WebizenID` keys in `identity/key_vault.rs`.
- **Instrument & Agent Honesty (`core-ontologies/agent-accountability.n3`)**: Software agents, AI models, and automated services operate with explicit capability credentials (`capability-credentials.n3`) and author-scoped delegation chains (`modalities/delegation.rs` ZCAP-LD). Per Webizen's core rule (*"Natural persons are not identity assets; instruments are not peers"*), every agent action carries cryptographic provenance tracing back to the authorizing `NaturalAgent` or `Group/Cooperative` quorum.
- **Handle-Plane (`Locators & Domains`)**: ICANN domain names (e.g., `ns.webcivics.net`, `webizen.au`), IP addresses, business registries (ABNs), and expiring `DNI` topological locators reside strictly on the **Handle-Plane**.
- **Continuity Invariant (`Handle revoke ≠ who-erase`)**: If a domain name expires or is seized, the `Collapse Detector` transitions the domain handle to `held/closed` on the locator plane without erasing any `NaturalAgent`, group membership, or `.q42` / Sanctuary Keep volume.

## 5. First-Class Support for QualiaDB / Webizen Native Applications & Multi-Tenant Sandboxing

Unlike traditional web hosts that only serve HTML/PHP/Node.js pages, `webizen-host` is a **native application server for the QualiaDB, Webizen, and Poet ecosystem**, while also replacing cPanel/WHM for standard web and Solid workloads.

### 5.1 Native QualiaDB / Webizen Application Families Supported on `webizen-host`
Every hosted instance natively packages, serves, and executes four classes of QualiaDB / Webizen applications across desktop (`webizen-desktop`), browser (`webizen-web` / WASM portal), and mobile (`qualia-mobile-harness`):
1. **Portable QApps & `qualia-app-contract` Applications (`q42/app_manifest/`, `q42/app_registry/`)**:
   - Hosts versioned **QApp** bundles conforming to `crates/qualia-app-contract` (the canonical portable command, context, session, and surface contract shared across **Poet**, **Webizen OS**, and **Storytold** applications) and the source-independent SDK boundary (`GA-17` / `SDK-01..10`).
   - Supports live multi-user and multi-agent state synchronization via append-only `.q42j` session journals (`q42/journal.rs`, `GameSessionJournal`) and Lamport/LWW CRDT merges (`foundation/crdt.rs`, `sync.rs`).
2. **VibeScript (`VBC1`) & Poet Manifold Applications (`crates/vibe/`, `crates/poet/`, `webizen-studio`)**:
   - Natively executes [VibeScript 0.1](https://webizen.au/progress-0.0.33.html) (`.vibe` compiled to `VBC1` bytecode)—providing reactive cell dependency DAGs (`reactive_cell.rs`) with sub-microsecond propagation, two-way data bindings (`bind <->`), declarative presentation sheaves (`present`), temporal tweens and springs, and multi-lingual locale support (`locale.rs`).
   - Exposes the fail-closed **~1,158 host catalog operations (`vibe/src/catalog/ids.rs`)** across ~90 capability families (`GraphDatabase`, `DeonticLogic`, `N3Logic`, `LegalLogic`, `ComputationalGeometry`, `Physics`, `Chemistry`, `Audio`, `Spectral`, `Cosmic`, `Inference`, `Orchestration`, `World`) plus the `poet/src/browser/*_chain_actions.rs` workbench manifolds and `vibe-play` (`:7420`) / `vibe-lsp` developer services.
3. **3D / 10D Spatial, Generative & Simulation Applications (`webizen-render`, `webizen-runtime`, `.10d`, `.hmc`)**:
   - Serves and steps multi-scale spatial applications built on the [Webizen 3D Engine](https://docs.google.com/file/d/1fugYZmVKAyEHwaTGV7ndznAObduUvEJn/view) (`SemanticScene` projecting SPARQL/N3 inference directly into 3D/WebGPU scenes with `q42:` provenance), the [Omniversal Coordinate System (OCS)](https://docs.google.com/document/d/1Auy3Y9gT-0yNPrlrdiTXfr5q5KBnPSAAXAL-mO4uyN0/edit), and `Chora` geospatial canvases (`domains/geospatial/spatial_sync.rs`).
   - Streams progressive `.10d` Living Containers (`QuantizedMesh`, `Tensor10DNodes`, `SkeletalAnimation` `SKL1` with VibeScript motor clips, `EntityOntology` `EONT1` affordances/ethograms, `SurfaceReading` `SRD1`, `HyperspectralCube`) and `QBDL` `.hmc` hypermedia bundles, while running authoritative 20 Hz fixed-timestep world reducers (`simulation/fixed_tick.rs`) and 42 MiB cellular logic graphs (`governance/cell_graph.rs`).
4. **Human-Centric Agentic, Neuro-Symbolic & Life-Domain Applications (`qualia-client-core`, `agent_runtime/`, `wellfare-core`)**:
   - Hosts the **Branching-Conversation Chat DAG (`qualia-client-core/src/chat_graph.rs`)** and consolidated `qualia-chat` services (`chat_{session,inference,retrieval,relay,agents,files,ontology,graph}`), symbolic multi-agent blackboards (`agent_runtime/orchestration.rs`), grammar-constrained VibeScript synthesis (`domino_gbnf.rs` + `neuro_symbolic_sieve.rs`), `.p64` model weight streaming (`q42/p64_weight.rs`), and the 640 KiB `webizen-lite-wasm` Ontology MCP endpoint.

### 5.2 Three-Tier Sandbox Architecture for Native Apps, Services & Websites
Every hosted application, domain, or group workspace runs inside an isolated **Host Cell (`net/peer/cells/` + `governance/cell_graph.rs`)** with explicit CPU, RAM, storage, and egress budgets:
1. **Tier 1: VibeScript (`VBC1`) & 42 MiB `SlgArena` Cellular Sandbox (Native Semantic & Poet Apps)**:
   - Every VibeScript function carries a mandatory `u64` instruction/cycle budget (`vibe/src/budget.rs`) and executes under a strict effect lattice (`Pure < Hot < Cold < Async < External` in `vibe/src/effects.rs`).
   - Capability-gated host calls are **fail-closed** (`using {Family};` leases checked by `deontic_interrupt.rs`), and hot-path reasoning runs inside an isolated **42 MiB `SlgArena` Sentinel cell** (`HotZeroHeap`).
2. **Tier 2: WebAssembly & QApp Isolate Sandbox (`vibe-wasm`, `webizen-lite-wasm`, `qualia-app-contract`)**:
   - Hosts compiled Rust/WASM QApp modules (`SDK-01..10`) and browser/mobile WASM packages scoped to virtual volume prefixes (`wasm_storage.rs`) and verified against `q42/app_manifest/`.
3. **Tier 3: W3C Solid LDP Pod Bridge & Linux/eBPF Container Sandbox (`qualia-solid-bridge` + `net/` eBPF)**:
   - Provides native W3C Solid Pods (`crates/qualia-solid-bridge`, matching the MIT baseline on [web.civics.au](https://web.civics.au/) with a strict Turtle↔`NQuin` boundary) alongside unprivileged Linux user/mount/network namespaces guarded by `qualia-core-db`'s native **eBPF packet/socket filter (`net/`)** for static/dynamic Web 2.0 sites.

## 6. QualiaDB-Accelerated DNS, Naming & QDNF Routing

`qualia-core-db` contains a dedicated `net/dns/` subsystem (wire codec, resolver, cache ring, quin records, ontology, SDN, lossless archive) alongside `net/qdnf/`. Integrating these into `webizen-host` delivers an authoritative and recursive DNS + QDNF naming engine that outperforms conventional BIND/CoreDNS stacks in latency, security, and semantic expressiveness.

### 6.1 How QualiaDB Accelerates DNS Performance (`net/dns/` + `NQuin` + `q_hash()`)
1. **Zero-Heap 48-Byte `NQuin` Zone & Cache Ring (`HotZeroHeap`)**:
   - Every DNS resource record (`A`, `AAAA`, `CNAME`, `TXT`, `SRV`, `HTTPS`, `SVCB`, `DNSKEY`, `RRSIG`, `TLSA`, plus custom `DID`/`Q42` records) is compiled into a **48-byte `NQuin`** inside `net/dns/`:
     - `subject`: 64-bit `q_hash()` (FNV-1a) of the normalized domain name + record type bits.
     - `predicate`: Record class/type and QDNF routing lane flags.
     - `object`: Inline packed IPv4/IPv6 address, DANE TLSA digest, TTL epoch, or `did:q42` pointer to a `Q42LEX v4` lexicon entry for long `TXT`/`HTTPS` payloads.
     - `context`: Authoritative zone DID and DNSSEC/Ed25519 signature status.
   - Lookups execute as **O(1) 64-bit integer hash probes** inside a pre-allocated, cache-line-aligned `HotZeroHeap` ring buffer (with optional Linux **AF_XDP / eBPF** packet filtering), resolving millions of queries per second with zero heap allocations.
2. **In-Flight Deontic & SHACL Policy DNS Firewall (`QPolicy` + `SlgArena`)**:
   - Evaluates **N3Logic and Deontic rules (`0x10–0x12`)** in-flight:
   - **Jurisdiction-Aware Routing (`jurisdiction.n3`)**: Steers traffic away from non-compliant relays based on the group's or person's deontic protection profile (`net/qdnf/profiles/` E16.1–E16.7).
   - **Split-Horizon Privacy & Consent Gating**: Private group, family, or agent service subdomains resolve **only** when the DNS query carries a valid `DNI` cookie, TSIG, or DoH/DoQ `WebizenID-TLS` session proof—returning `NXDOMAIN` to public scanners.
3. **Bitemporal Lossless DNS Archive (`net/dns/` lossless archive)**:
   - Every zone mutation and DNSSEC/DANE key rollover is journaled in `.q42j` with bitemporal predicates (`lifecycle:validFrom`, `lifecycle:transactionFrom`), providing a tamper-evident evidentiary chain ("Continuity for a jury" per [QDNF](https://webizen.au/qdnf.html)).

### 6.2 Dual-Stack QDNF Naming & Cryptokey Routing
Hosted domains and native applications operate simultaneously across the legacy Internet and the **Qualia Decentralized Network Fabric (QDNF)**:
- **Legacy Internet Gateway**: Serves UDP/TCP `:53` (with DNSSEC and DANE), DoH, DoT, and DoQ, automatically publishing `_did.<domain>` `TXT` records and `.well-known/did.json` / `.well-known/qdnf` descriptors.
- **Native QDNF Honeycomb Stack (`net/qdnf/`)**:
  - **`QLink` & `DNI`**: Proves neighbour adjacency cryptographically and assigns self-certifying, expiring topological locators (`DNI`).
  - **`QRoute` & Cryptokey IPv6 (`governance/web_civics.rs`)**: Uses constraint-first routing (`validate → index → plan` in `net/qdnf/route/`) and deterministic **Ed25519 → ULA IPv6 derivation** (`fd00::/8` cryptokey routing where the mathematical DID key *is* the overlay IPv6 address over `SocialWebNet` WireGuard or raw Ethernet).
  - **`QResolve` (`net/qdnf/resolve/qsr`)**: Resolves `did:qi`, `did:q42`, and content-addressed `.q42`/`.hmc` hashes directly across the peer fabric without touching ICANN DNS.

## 7. User-Powered Decentralized CDN & Egress Protection (Solving `ns.webcivics.net`)

To ensure no Webizen person or group ever faces the runaway CloudFront bandwidth bills experienced on [ns.webcivics.net](https://ns.webcivics.net/), every hosted domain, native QApp, and ontology volume on `webizen-host` is backed by a **User-Powered Decentralized CDN (`Q-CDN`)** with hard origin cost caps.

### 7.1 How the User-Powered Decentralized CDN Works
1. **Origin Serves Lightweight Signed Root Index (<10 KiB)**:
   - When a client requests a resource from `ns.webcivics.net` or any hosted domain/QApp, the origin VPS serves the compact, Ed25519-signed **Master Index** (`cbor_ld_manifest.rs` / `BIDX` header) cataloging the SHA-256 / BLAKE3 digest, byte offset, and micropayment weight of every 40 KiB `.q42` SuperBlock, `.10d` section, or `.hmc` segment.
2. **Three-Tier Peer Swarm Distribution (`QPR` + WebTorrent `:4242` + Browser OPFS)**:
   - **Tier A — Cooperative & Group VPS Mirrors (`net/peer/replication/`)**: Other `webizen-host` VPS instances replicate hot `.q42`, `.10d`, and `.hmc` shards using Merkle custody proofs, advertised via DNS `HTTPS`/`SVCB` and HTTP `Alt-Svc` headers.
   - **Tier B — Desktop User & Agent Nodes (`webizen-desktop` via `qualia-peer`)**: Every user running `webizen-desktop` caches the `.q42` SuperBlocks and `.hmc` QApp/ontology assets they use locally and seeds verified slices to peers over `QSession/QSync` and the built-in daemon seeder (`services/webtorrent_*.rs` on port `:4242`).
   - **Tier C — Browser Visitors (OPFS Cache + WebRTC/WebTorrent)**: Browser visitors cache fetched 40 KiB SuperBlocks in their Origin Private File System (OPFS, `wasm_storage.rs`) and exchange chunk-verified slices via WebRTC DataChannels.
3. **Hard Origin Egress Circuit Breaker (`net/qdnf/economics/meters.rs`)**:
   - The operator or group quorum sets a strict monthly or daily egress byte and dollar ceiling in `meters.rs` (e.g., *"Max 1.5 TB/month direct origin egress; $0.00 allowed overage"*) enforced by the Sentinel VM's anti-usury circuit breaker opcodes (`governance/coordination.rs`).
   - Above the threshold (such as during a US data-hub traffic surge), the origin VPS continues serving the tiny signed Root Index and verified Humanitarian ICT sessions directly, while redirecting all bulk `.q42`/`.hmc` range fetches (`HTTP 307` / `QResolve` swarm pointers) to the user-powered `Q-CDN` swarm or commercial toll-gated mirrors—capping hosting costs at the flat monthly VPS fee.

## 8. Micropayments, Permissive Commons Economics & Blockchain / DLT Architecture

To make [ns.webcivics.net](https://ns.webcivics.net/), [WebCivics/ns](https://github.com/WebCivics/ns), native QApps, and [Ecosphere Assets](https://docs.google.com/document/d/1WMoe6hn39ZnLFXl0T0KEWTW8zCBkdvduov2wctHZPsM/edit) financially self-sustaining while keeping human-rights and humanitarian infrastructure free for natural persons, `webizen-host` wires the **Permissive Commons Economic Engine (`crates/qualia-core-db/src/modalities/value_flow.rs`)** and **QDNF Metering Substrate (`net/qdnf/economics/meters.rs`)** to protocol-level micropayments and a three-tier Blockchain/DLT architecture.

### 8.1 Two-Loop Permissive Commons Economic Model (`modalities/value_flow.rs`)
1. **Loop 1 — Capital Creation Recovery (`Obligation Cost` & Automatic `10x` Commons Sunset)**:
   - Processing and curating large ontologies (`WebCivics/ns`), native QApps, or Ecosphere corpora incurs verifiable engineering and compute costs recorded in `cbor_ld_manifest.rs` as the baseline **Obligation Cost (`C_obligation`)**, with a capped recovery ceiling of **up to `10x C_obligation`** computed via `commons_cost(production_cost, roi_cap_percent, max_roi_percent)` and guarded by `usury_ceiling()` and `check_usury()`.
   - **Natural Persons, Community Groups & Humanitarian ICT (`humanitarian-ict.n3`)**: Granted immediate, $0 royalty access (`royalty()` multiplier = `0%`).
   - **Commercial Legal Entities (Corporations, Commercial AI Hubs, Scrapers)**: Gated by **HTTP `402 Payment Required` / `QPolicy` Toll Gates**. Commercial payments accumulate via `pool_after()` and `accumulate_meter_to_pool()`.
   - **Self-Extinguishing Commons Sunset (`is_commons_discharged`)**: Once cumulative commercial tolls reach the capped obligation cost, `CommonsObligation::discharge_to_commons()` fires automatically—transitioning the volume to `PermissiveRoutingLane::EnforcePermissiveCommons` (`0b01`) for all users globally ("Ending Digital Slavery" per [GuideForDevelopers](https://devdocs.webizen.org/GuideForDevelopers/)).
2. **Loop 2 — Decentralized CDN & Agent Compute Micropayments (Paying Users, Groups & Hosts)**:
   - `net/qdnf/economics/meters.rs` measures exact `MeterKind::{Bytes, EnergyJoules, Time, Compute}` per session and calculates deterministic carriage fees via `value_flow.rs::carriage_fee_from_meters()`, streaming micropayments directly to the **peer users (`webizen-desktop` seeders)**, **group hosts**, and **`services/swarm/` verify-before-pay compute agents** that supplied the verified bandwidth and compute.

### 8.2 Multi-Blockchain, Multi-Exchange & Energy-Cheap Post-Quantum DLT Architecture

Based on these modules, `webizen-host` adopts a **Multi-Chain, Multi-Exchange & Post-Quantum Native Ledger Architecture**:
